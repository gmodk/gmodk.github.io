In the long periods of my existence,
I have developed the inconvenient habit of asking mathematical questions
about things that probably never asked to be mathematical.

These pieces of text are an ultimately hopeless endeavor, a futile attempt,
to put some order into these questions, formalize their underlying structures,
and see what happens when intuition is made to account for itself.

Mathematics, after all, is a rather tuxedo way of discovering
just how estrange a question can become once we ask it properly.

What invariants would have to persist through development for we to say that one evolving system remains numerically the same individual?   a) Set up Let the function \(\phi: P x C \to R\) to map a tuple \((p,c)\) to a realization \(r\), where \(p \in P\) is a program and \(c \in C\) is a contingency (history). Let the map \(H_{\alpha}: R \to D_{\alpha}\) to extract the organization into some descriptive level. Then, we have: $$ H_{\alpha}(P,C) = H_{\alpha}(\phi(p,c)) $$ which is the realized organization along a particular path.   b) Formally The path-dependent part is the variation of the \(H_{\alpha}\) over \(C\). If \(C\) has a probability measure \(\mu\), we define its predictable component by: $$ \bar{H}_{\alpha}(p) = \int_{c}^{\infty} H_{\alpha}(p,c) \, d{\mu(c)} = E[H_{\alpha} | P = p] $$ And the path-dependent derivation by: $$ \Delta_{\alpha}(p,c) = H_{\alpha} - \bar{H}_{\alpha}(p-c) $$   c) Conclusion We conclude, therefore that: $$ H_{\alpha}(p,c) = H_{\alpha}(p) + \Delta_{\alpha}(p,c) $$ where: - \(H_{\alpha}(p)\) is the predictable path from \(p\). \(\Delta_{\alpha}(p,c)\) is the history dependant path. But the integral represents an expected or predictable component, not necessarily strcited predetermined information, which would required invariance across all \(c \in C\).   d) Intuitevely The program defines what can systematically be expected across all possible histories, while (\(H_{\alpha}(p) \circ \phi\)) captures what actually emerges in one particular history.   2. program_execution_individual::(1/2)

    What mathematical distinctions would we need to separate a Program, its Execution, and an emergent Individual without assuming in advance that these are three different ontological kinds?   a) Set up Let \(P\) be a genrative structure, \(C\) the space of initial conditions or contingences, and \(I\) the space of possible realizations. We define a map \(\phi: P x C \to I\): Supose \(R = Im(\phi)\) is the set of realizable executions. A level of description is then given by a structure preserving map: $$ H_{\alpha}: R \to D_{\alpha} $$ with \(R = Im(\phi) \subseteq I\) and \(\phi(P,C) = i\)   b) Formally For each descriptive map \(H_{\alpha}\), we define: $$ r_1 ~ r_2 <=> H_{\alpha}(r_1) = H_{\alpha}(r_2) $$ Then, the descriptive level is the quotient: $$ D_{\alpha} \cong \frac{R}{r_{\alpha}} $$ This is equivalent to: $$ \frac{R}{Ker H_{\alpha}} \cong Im H_{\alpha} $$   c) Conclusion The program, its execution and the emergent individual need not to be three different ontological kinds. They can be understood as different mathematical roles within one structure, where: P specifies possibilites. R contains realized trajectories. An individual can be represented as an equivalence class \([r_{\alpha}]\) at a chosen description level \(D_{\alpha}\).   d) Intuitevely The idea is that a system contains more detail that any description of that system prserveres. The map \(\phi\) generates actual realizations from the program, while each \(H_{\alpha}\) forgets some distinctions and keeps others.
